## Notes

- **gryps-finance/assay** is the standout red flag: extremely polished documentation (pre-registration study, 17-endpoint API reference, findings writeup) describing a CLI/MCP-server/Claude-plugin product, but the actual git tree contains zero source files — every `package.json` bin/script entry, `.mcp.json` reference, and README command points at files that don't exist. This fails Functionality outright and the Docs "<10 min" bar (nothing runs).
- **osr21/wallet-witness** looks like solid Nansen integration on the surface (5+ endpoints, clean read-only design, good README) but the buildathon's core Data Integration ask fails: the "correct answer" a player is scored against is a hardcoded seed label, not derived from the live Nansen payload shown as a "clue."
- **FalcoN-demo/Peregrine** and **witman01/ThesisArena** are the strongest submissions in this batch: both have Nansen data feeding real, weighted decision/scoring pipelines (not display), are read-only or non-custodial, and ship README instructions that a builder could run in under 10 minutes. Peregrine additionally has functioning (non-custodial) trade execution and the deepest endpoint coverage.
- **bestashok/nansen-smart-money-rotation-radar** is the clearest and most literal answer to "exit side" of the batch — it explicitly fetches Nansen's SELL-side wallet data and joins it against BUY-side data on other tokens to detect rotation, with an unusually thorough, self-critical README (including a disclosed budget-guard bug postmortem).
- **trunghieud/Meridian_Buildathon** and **OpenDeltaLabs/tendril-nansenai-meridian** sit in the middle: both integrate real Nansen data and have honest docs about their limits (Tendril's execution layer is gated behind a closed beta; the meme-dashboard's flashiest numbers are a static snapshot), but neither meaningfully clears the "drives logic, not display" bar with much depth.
- One audit (nansen-signal-runner) flagged as unverified: no independent run was performed against the live `/api/run-data` endpoint (no Nansen API key available to the auditor) — "live pricing works end-to-end without crashing" rests on code reading plus the repo's own self-reported verification, not an independent execution.
